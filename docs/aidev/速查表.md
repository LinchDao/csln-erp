# GitHub Copilot Codex CLI 专属速查表（ERP全栈开发版）
> 针对你日常的 **Java后端(Spring Boot/MyBatis-Plus) + 前端(Vue/Element UI) + 数据库(MySQL)** ERP系统开发场景，精简了高频实用命令，附场景化用法，直接复制即用。

---

## 🚀 核心高频命令（90%开发场景覆盖）
| 命令 | 核心作用 | 开发场景示例 |
|------|----------|--------------|
| `/new` | 开启全新对话 | 切换开发模块（如从商品管理→采购管理），直接输入`/new`新建干净会话 |
| `/rename` | 重命名对话 | `/rename "ERP采购单模块接口开发"`，方便后续快速检索历史对话 |
| `/compact` | 压缩对话上下文 | 开发到一半上下文太长、响应变慢，输入`/compact`一键总结，节省token |
| `/clear` | 重置会话 | 彻底清空历史，相当于重启CLI，输入`/clear` |
| `/copy` | 复制最新输出 | 生成完代码直接输入`/copy`，一键复制到剪贴板，不用手动选中 |
| `/model` | 切换模型/推理强度 | 复杂需求（如多表联查、复杂前端组件）用高推理模型，简单需求用快速模型 |
| `/fast` | 开启极速模式 | 简单代码生成、快速补全，输入`/fast`开启，响应翻倍（消耗2倍用量） |
| `/status` | 查看会话状态 | 随时输入`/status`，查看当前模型、token用量、权限配置 |
| `/diff` | 查看Git变更 | 开发完输入`/diff`，让Codex基于Git diff做代码审查、优化 |
| `/review` | 自动代码审查 | 直接输入`/review`，让Codex检查当前代码的Bug、规范、性能问题 |
| `/mention` | 引用项目文件 | 让Codex基于已有代码开发，如`/mention src/main/java/com/csln/erp/service/GoodsService.java` |
| `/init` | 初始化AGENTS.md | 项目根目录输入`/init`，生成AGENTS.md，写入ERP项目规范、技术栈要求 |

## 🧩 模块开发专属命令
### 1. 后端开发（Spring Boot/MyBatis-Plus）
| 命令 | 用法场景 |
|------|----------|
| `/init` | 生成AGENTS.md，写入「遵循MyBatis-Plus 3.5+规范、Swagger3注解、统一返回体」等后端规范 |
| `/review` | 写完Controller/Service后，输入`/review`检查接口规范、参数校验、异常处理 |
| `/diff` | 提交代码前，`/diff`让Codex基于变更做代码优化、补全缺失逻辑 |
| `/permissions` | 配置文件读写权限，确保Codex可安全修改后端代码 |
| `/sandbox-add-read-dir` | 给沙箱授权项目目录：`/sandbox-add-read-dir /your/project/path/csln-erp` |

### 2. 前端开发（Vue/Element UI）
| 命令 | 用法场景 |
|------|----------|
| `/personality` | 选择「前端开发专家」风格，让Codex输出符合Element UI规范的组件代码 |
| `/copy` | 生成完组件代码直接`/copy`，快速粘贴到Vue文件 |
| `/review` | 检查前端代码的响应式、样式、组件复用、性能优化 |
| `/mention` | 引用已有Vue组件，让Codex基于现有组件做扩展 |

### 3. 数据库开发（MySQL）
| 命令 | 用法场景 |
|------|----------|
| `/mention` | 引用`schema.sql`/表结构文件，让Codex生成符合现有表结构的SQL |
| `/review` | 生成完建表/修改表SQL后，`/review`检查语法、索引、数据类型合理性 |
| `/diff` | 基于SQL变更文件，让Codex做数据迁移逻辑校验 |

## ⚙️ 会话与协作管理
| 命令 | 用法场景 |
|------|----------|
| `/fork` | 同一个需求探索两种方案（如两种采购单实现逻辑），输入`/fork`分叉对话，互不影响 |
| `/resume` | 中断开发后，输入`/resume`快速恢复之前的ERP开发对话 |
| `/plan` | 复杂需求（如采购单全流程开发），先输入`/plan`让Codex输出开发计划，再分步实现 |
| `/collab` | 团队协作开发ERP，输入`/collab`开启多人协作模式，共同编辑对话 |

## 💡 开发流程最佳实践
1.  **新建任务**：`/new` → `/rename` → `/init`（写入项目规范）
2.  **需求开发**：复杂需求先`/plan`，再分步开发；简单需求直接开发
3.  **代码优化**：开发完`/diff` → `/review`，检查问题、优化代码
4.  **会话管理**：上下文过长`/compact`，切换任务`/new`，重置`/clear`
5.  **效率提升**：简单代码`/fast`，生成完`/copy`，引用文件`/mention`
